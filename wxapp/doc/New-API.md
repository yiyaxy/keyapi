
## 1. 项目定位

这是一个基于 `new-api` 后端能力构建的 **C 端微信小程序 MVP**，只面向普通个人用户，不包含任何管理后台能力。

### 核心目标
1. 用户通过 **账号密码登录**
2. 用户查看自己的 **余额、用量、API Key**
3. 用户通过 **兑换码** 完成额度充值
4. 用户通过 **邀请码** 进行拉新，并查看邀请奖励

### 明确不做
- 不做管理后台
- 不做在线支付
- 不做复杂模型广场
- 不做管理员权限
- 不做复杂统计图表
- 不做微信授权登录
- 不做多角色体系

---

## 2. 用户角色

- 登录

## 7. 页面详细信息架构

## 7.1 登录页 `/login`

### 页面目标

让用户使用 **账号密码** 完成登录。

### 页面模块

#### 1）顶部品牌区

- Logo
- 产品名称
- 简短说明

#### 2）登录表单区

- 账号输入框
- 密码输入框
- 登录按钮

#### 3）辅助操作区

- 忘记密码（可预留）
- 注册入口（可预留，若当前不开放可隐藏）

### 表单校验

- 账号不能为空
- 密码不能为空
- 登录中按钮禁用，防止重复提交

### 登录成功后

跳转到 `/home`

---

## 7.2 首页 `/home`

### 页面目标

展示用户最核心的账户数据，并提供快捷操作入口。

### 页面模块

#### 1）顶部用户信息区

- 欢迎语
- 用户名
- 用户 ID（可选）

#### 2）账户总览卡片

- 当前余额
- 今日消耗
- 本月消耗
- 账户状态（正常/受限，可选）

#### 3）快捷功能入口

- 兑换码充值
- 查看 API Key
- 查看消费记录
- 前往邀请页

#### 4）邀请收益卡片

- 我的邀请码
- 已邀请人数
- 待转换奖励
- 去邀请按钮

### 首页核心原则

- 信息简单
- 数据直观
- 操作路径短
- 首页直接承接“充值”和“拉新”

---

## 7.3 兑换码页 `/redeem`

### 页面目标

让用户通过兑换码完成额度充值。

### 页面模块

#### 1）说明区

- 标题：兑换码充值
- 简短说明：输入兑换码后可为当前账户增加额度

#### 2）输入区

- 兑换码输入框
- 提交兑换按钮

#### 3）结果反馈区

- 兑换成功提示
- 兑换失败提示
- 当前余额刷新结果

### 页面逻辑

- 输入为空时不可提交
- 提交成功后刷新用户余额
- 成功后可返回首页
- 支持错误提示，例如兑换码无效、已使用、已过期

---

## 7.4 邀请页 `/invite`

### 页面目标

让用户完成邀请拉新，并清晰感知邀请收益。

### 页面模块

#### 1）邀请码区

- 我的邀请码
- 复制邀请码按钮

#### 2）邀请数据区

- 已邀请人数
- 累计奖励
- 待转换奖励
- 已转换额度

#### 3）奖励操作区

- 转换奖励按钮
- 转换说明

#### 4）规则说明区

- 邀请规则
- 奖励发放规则
- 奖励转换规则

### 页面核心要求

- 该页面必须是独立主页面
- 邀请机制不能埋在“我的”里
- 页面重点不是“展示邀请码”，而是“展示邀请收益闭环”

### 邀请闭环

复制邀请码 -> 邀请他人注册 -> 获得奖励 -> 转换为账户额度

---

## 7.5 我的页 `/profile`

### 页面目标

展示个人资料与账户相关入口。

### 页面模块

#### 1）个人信息区

- 用户名
- 用户 ID
- 当前余额

#### 2）功能入口区

- API Key
- 消费记录
- 兑换码充值
- 邀请中心

#### 3）操作区

- 退出登录

### 页面原则

- 只放个人相关内容
- 不承载首页核心业务数据
- 保持简洁

---

## 7.6 API Key 页 `/apikey`

### 页面目标

让用户查看并复制自己的 API Key。

### 页面模块

#### 1）Key 展示区

- API Key 文本
- 遮罩展示或完整展示（按安全策略决定）

#### 2）操作区

- 复制 Key 按钮

#### 3）说明区

- Key 用途说明
- 安全提醒

### 页面原则

- 重点突出“复制”
- 不做复杂管理
- 不做批量 Key 管理

---

## 7.7 消费记录页 `/usage-records`

### 页面目标

让用户查看最近的消费记录和用量明细。

### 页面模块

#### 1）顶部统计区

- 最近消费总额（可选）
- 最近调用次数（可选）

#### 2）记录列表区

每条记录包含：

- 时间
- 模型名称
- 请求状态
- 扣费金额

### 页面原则

- 只展示最近记录
- 不做复杂筛选
- 不做导出
- 不做图表

## 12. 交互与状态要求

## 全局要求

- 所有请求都要有加载态
- 所有失败都要有 toast 提示
- 登录失效时自动跳回登录页
- 数据为空时展示空状态页
- 复制成功后要有提示

## 页面状态

### 登录页

- 初始态
- 提交中
- 登录失败
- 登录成功

### 首页

- 加载中
- 正常展示
- 数据为空
- 接口异常

### 兑换码页

- 未输入
- 可提交
- 提交中
- 成功
- 失败

### 邀请页

- 加载中
- 正常展示
- 无邀请数据
- 转换处理中
- 转换成功
- 转换失败
