# 微信小程序接口域名迁移设计

## 结论

将微信小程序源码中仍指向 `https://token.cymoon.cn` 的请求地址和 H5 聊天地址统一迁移到 `https://token.mooschh.com`，重新构建并发布小程序。数据库中的 `ServerAddress` 不会改变已经编译进小程序安装包的地址，因此必须发布新版小程序才能让 iPhone 客户端使用新域名。

## 方案比较

1. **直接替换源码中的旧域名（采用）**：改动范围最小，可直接修复当前扫码登录和 H5 聊天入口，发布风险最低。
2. **增加构建环境变量**：更适合同时维护开发、测试和生产环境，但本次只有一个生产域名，新增配置体系会扩大范围。
3. **保留旧域名并依赖 HTTP 跳转**：不需要重新发布，但不同微信客户端对跳转和响应解析的行为不一致，正是当前 iPhone 失败的风险来源，因此不采用。

## 变更范围

- `wxapp/src/config/env.js`：将 API 基础地址改为 `https://token.mooschh.com`。
- `wxapp/src/pages/apps/index.vue`：将 H5 聊天地址改为 `https://token.mooschh.com/m/chat`。
- 不修改后端接口、数据库、微信 AppID、登录流程或服务器配置。

## 数据流

小程序启动、扫码查询和扫码确认继续通过现有请求封装访问 `env.basePath`；应用页的 H5 聊天入口继续使用固定 URL。唯一变化是两个入口的主机名从旧域名切换到新域名，接口路径和响应处理保持不变。

## 异常处理

沿用现有的请求超时、HTTP 状态码和空响应提示逻辑。本次不改变“响应数据为空”等用户提示，避免将域名迁移与错误交互重构混在一起。

## 测试与验收

1. 先增加静态回归检查，并确认它会因源码仍包含旧域名而失败。
2. 修改域名后，回归检查必须确认小程序源码不再包含 `token.cymoon.cn`，且两个入口均使用 `token.mooschh.com`。
3. 执行微信小程序生产构建 `pnpm build:mp-weixin`，要求退出码为 0。
4. 发布后在 iPhone 真机重新进入小程序，验证扫码查询、确认登录和网页端登录完成流程；此项需要在微信公众平台上传并发布新版后完成。

## 发布影响

源码和构建产物的验证可以在本地完成；用户端修复生效还需要通过微信开发者工具上传、审核并发布新版。已经缓存旧版本的 iPhone 可能需要删除最近使用记录后重新进入。
