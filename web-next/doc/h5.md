# AI 形象诊断 H5 应用快速开发方案

> 项目目标：不改动 LobeHub，不做复杂平台内嵌，不重构现有平台。  
> 直接开发一个平台内 H5 形象诊断应用页面，通过小程序 WebView 打开，复用现有登录、接口、数据库、文件上传能力。  
> 后端调用视觉大模型生成结构化报告 JSON，前端使用固定模板渲染高级报告，并使用 `html2canvas` 生成报告长图。

---

## 1. 项目结论

本项目第一版采用最短路径：

```text
平台 / 小程序入口
  ↓
WebView 打开 H5 形象诊断页
  ↓
用户上传照片
  ↓
调用后端形象诊断接口
  ↓
后端调用视觉大模型生成报告 JSON
  ↓
前端固定模板渲染高级报告
  ↓
前端使用 html2canvas 生成长图
  ↓
用户保存 / 分享报告
```

本阶段不处理：

- 不接 LobeHub
- 不做 LobeHub Skill
- 不做复杂应用市场协议
- 不做独立账号系统
- 不做扣费
- 不做复杂图片算法
- 不做多模板管理
- 不做 PDF
- 不做外部开发者共创体系

本阶段只做一个可快速上线、可演示、体验完整的 H5 AI 形象诊断应用。

## 3. 产品流程

### 3.1 用户主流程

```text
1. 用户从小程序点击「AI 形象诊断」
2. 小程序 WebView 打开 H5 页面
3. H5 自动识别登录态 / 用户信息
4. 用户上传一张正脸照片
5. 用户选择诊断目标
6. 用户点击「开始诊断」
7. 前端提交图片 URL 和诊断目标
8. 后端创建诊断任务
9. 页面进入分析中状态
10. 前端轮询任务状态
11. 后端完成大模型分析并保存报告 JSON
12. 前端获取报告 JSON
13. 前端渲染完整报告
14. 用户点击「生成长图」
15. 前端用 html2canvas 生成长图
16. 用户长按保存或分享
```

## 4. H5 页面设计

第一版只需要 3 个核心页面状态：

```text
上传页
分析中页
报告页
```

如果使用单页应用，也可以用一个页面内的状态切换实现。

---

### 4.1 上传页

#### 页面目标

让用户快速理解这个应用能做什么，并完成照片上传。

#### 页面内容

- 产品标题
- 简短介绍
- 示例报告入口或示意卡片
- 上传照片区域
- 拍摄要求说明
- 风格目标选择
- 开始诊断按钮

#### 推荐文案

```text
AI 个人形象诊断

上传一张正脸照，生成你的专属形象报告：
四季色彩、妆容、发型、发色、饰品、穿搭、眼镜一次分析。
```

#### 拍摄要求

```text
建议上传自然光下的正脸照片
不要使用浓妆或强美颜
尽量露出额头和头发
照片中只保留一个人
背景尽量干净
```

#### 风格目标选项

```text
日常变美
通勤显气质
约会氛围感
职场专业感
轻熟高级感
```

#### 字段映射

| 展示文案 | 提交值 |
|---|---|
| 日常变美 | daily_beauty |
| 通勤显气质 | commute |
| 约会氛围感 | dating |
| 职场专业感 | workplace |
| 轻熟高级感 | elegant |

### 4.2 分析中页

#### 页面目标

减少等待焦虑，让用户感觉 AI 正在认真分析。

#### 页面内容

- 进度条
- 分析步骤文案
- 用户上传照片缩略图
- 温和提示

#### 分析文案

```text
正在识别你的肤色冷暖……
正在分析五官线条与脸型……
正在匹配四季色彩类型……
正在生成妆容与发型建议……
正在生成穿搭与眼镜建议……
正在生成你的专属形象报告……
```

#### 进度策略

前端可以使用假进度增强体验：

```text
0 - 20%：上传照片
20 - 40%：识别视觉特征
40 - 60%：匹配色彩模型
60 - 80%：生成形象建议
80 - 95%：生成报告
95 - 100%：等待后端完成
```

如果后端返回实际进度，则优先使用后端进度。

## 7. 后端接口设计

接口应尽量少，第一版建议 3 个接口即可。

---

### 7.1 创建形象诊断任务

```http
POST /api/app/image-diagnosis/create
```

#### 请求参数

```json
{
  "imageUrl": "https://cdn.example.com/upload/user-photo.jpg",
  "styleGoal": "daily_beauty"
}
```

#### 返回参数

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": "diag_20260429_001",
    "status": "processing"
  }
}
```

---

### 7.2 查询诊断任务状态

```http
GET /api/app/image-diagnosis/task/{taskId}
```

#### 处理中返回

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": "diag_20260429_001",
    "status": "processing",
    "progress": 60,
    "message": "正在生成穿搭风格建议"
  }
}
```

#### 完成返回

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": "diag_20260429_001",
    "status": "completed",
    "progress": 100,
    "reportId": "report_20260429_001"
  }
}
```

#### 失败返回

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": "diag_20260429_001",
    "status": "failed",
    "progress": 100,
    "errorMessage": "照片未检测到清晰正脸，请重新上传"
  }
}
```

## 8. 后端处理逻辑

### 8.1 创建任务流程

```text
1. 接收 imageUrl 和 styleGoal
2. 获取当前登录用户 userId
3. 创建任务记录
4. 状态设为 processing
5. 异步执行大模型分析
6. 立即返回 taskId
```

### 8.2 异步分析流程

```text
1. 读取任务信息
2. 调用视觉大模型
3. 要求模型直接输出指定 JSON
4. 解析 JSON
5. 校验必要字段
6. 保存报告记录
7. 更新任务状态为 completed
8. 如果失败，更新任务状态为 failed
```

### 8.3 第一版可以同步还是异步？

建议使用异步任务。

原因：

- 视觉大模型耗时不稳定
- 小程序 WebView 等待时间不宜过长
- 方便前端展示进度
- 后续可以接入队列

如果开发时间很紧，也可以接口内部同步调用模型，但前端仍然按任务轮询设计，便于后续升级。

## 9. 数据库设计

如果已有通用任务表和报告表，可以复用。  
如果没有，第一版新增两张表即可。

---

### 9.1 形象诊断任务表

```sql
CREATE TABLE ai_image_diagnosis_task (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
  task_id VARCHAR(64) NOT NULL UNIQUE COMMENT '任务ID',
  user_id BIGINT NOT NULL COMMENT '用户ID',
  image_url VARCHAR(1024) NOT NULL COMMENT '用户上传图片URL',
  style_goal VARCHAR(64) DEFAULT NULL COMMENT '风格目标',
  status VARCHAR(32) NOT NULL COMMENT 'processing/completed/failed',
  progress INT DEFAULT 0 COMMENT '任务进度',
  error_message VARCHAR(1024) DEFAULT NULL COMMENT '错误信息',
  created_at DATETIME NOT NULL COMMENT '创建时间',
  updated_at DATETIME NOT NULL COMMENT '更新时间',
  INDEX idx_user_id (user_id),
  INDEX idx_task_id (task_id),
  INDEX idx_status (status)
) COMMENT='AI形象诊断任务表';
```

---

### 9.2 形象诊断报告表

```sql
CREATE TABLE ai_image_diagnosis_report (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
  report_id VARCHAR(64) NOT NULL UNIQUE COMMENT '报告ID',
  task_id VARCHAR(64) NOT NULL COMMENT '任务ID',
  user_id BIGINT NOT NULL COMMENT '用户ID',
  image_url VARCHAR(1024) NOT NULL COMMENT '用户上传图片URL',
  summary_json JSON DEFAULT NULL COMMENT '报告摘要JSON',
  report_json JSON NOT NULL COMMENT '完整报告JSON',
  report_image_url VARCHAR(1024) DEFAULT NULL COMMENT '报告长图URL，第一版可为空',
  created_at DATETIME NOT NULL COMMENT '创建时间',
  updated_at DATETIME NOT NULL COMMENT '更新时间',
  INDEX idx_user_id (user_id),
  INDEX idx_report_id (report_id),
  INDEX idx_task_id (task_id)
) COMMENT='AI形象诊断报告表';
```

如果数据库不支持 JSON 字段，可以将 `summary_json` 和 `report_json` 改为 `LONGTEXT`。

## 12. 后端兜底逻辑

视觉大模型可能返回异常 JSON，需要做兜底。

### 12.1 必须校验

- 是否是合法 JSON
- 是否包含 `imageQuality`
- 是否包含 `profileSummary`
- 是否包含 `seasonColor`
- 是否包含 `makeup`
- 是否包含 `hairstyle`
- 是否包含 `outfit`
- 是否包含 `finalAdvice`

### 12.2 图片质量拦截

如果以下条件成立，任务标记为失败：

```text
imageQuality.faceDetected = false
imageQuality.lighting = poor 且 confidence < 0.5
imageQuality.angle = side
imageQuality.confidence < 0.45
```

失败提示：


## 15. html2canvas 生成长图

### 15.1 安装

```bash
npm install html2canvas
```

### 15.2 示例代码

```js
import html2canvas from 'html2canvas'

async function generateReportImage() {
  const el = document.getElementById('report-container')
  if (!el) return

  const canvas = await html2canvas(el, {
    scale: 2,
    useCORS: true,
    allowTaint: false,
    backgroundColor: '#F7F2EA'
  })

  const dataUrl = canvas.toDataURL('image/png')

  return dataUrl
}
```

## 17. 前端接口调用流程

### 17.1 开始诊断

```js
async function startDiagnosis() {
  if (!imageUrl) {
    showToast('请先上传照片')
    return
  }

  const res = await request.post('/api/app/image-diagnosis/create', {
    imageUrl,
    styleGoal
  })

  const taskId = res.data.taskId
  goToLoading(taskId)
}
```

### 17.2 轮询任务

```js
function pollTask(taskId) {
  const timer = setInterval(async () => {
    const res = await request.get(`/api/app/image-diagnosis/task/${taskId}`)
    const data = res.data

    updateProgress(data.progress, data.message)

    if (data.status === 'completed') {
      clearInterval(timer)
      goToReport(data.reportId)
    }

    if (data.status === 'failed') {
      clearInterval(timer)
      showError(data.errorMessage || '诊断失败，请重新上传照片')
    }
  }, 1500)
}
```

### 17.3 获取报告

```js
async function loadReport(reportId) {
  const res = await request.get(`/api/app/image-diagnosis/report/${reportId}`)
  report.value = res.data.report
}
```
