# AI 个人形象诊断多子应用方案

> 核心调整：不再追求“一次上传、一次生成全部内容”。  
> 改为：用户进入 AI 形象诊断应用后，可以自由选择不同的诊断子应用。  
> 每个子应用独立完成一个明确任务，互不强依赖，减少开发复杂度、模型成本和等待时间。

---

## 1. 项目定位

本项目是一个放在小程序 WebView 内使用的 H5 AI 形象诊断应用。

它不是单一的大报告生成器，而是一个由多个轻量 AI 子应用组成的个人形象工具集合。

用户可以按自己的需求选择：

- 四季色彩诊断
- 妆容诊断
- 发型诊断
- 发色诊断
- 饰品诊断
- 穿搭风格诊断
- 眼镜诊断
- VS 风格对比

每个功能都是一个独立子应用，用户想用哪个就点哪个。

---

## 2. 为什么要这样调整

### 2.1 一次性全量生成的问题

如果用户上传一张照片后，系统一次性生成：

- 四季色彩
- 妆容
- 发型
- 发色
- 饰品
- 穿搭
- 眼镜
- VS 对比
- 多张案例图
- 完整报告长图

会出现几个问题：

| 问题 | 影响 |
|---|---|
| 生成时间长 | 用户等待焦虑，容易退出 |
| 模型成本高 | 每次调用消耗过大 |
| 失败率高 | 任意一个模块失败都会影响整体体验 |
| 开发复杂 | 后端任务编排、状态同步、错误处理都会变复杂 |
| 用户需求不一定全量 | 用户可能只想看穿搭、发型或色彩 |
| 结果页面过重 | 手机端阅读压力大 |

所以第一版不建议做“一步到位全量生成”。

## 3. 新的产品原则

### 3.1 核心原则

```text
首页做入口聚合
每个诊断功能做成独立子应用
用户自选使用哪个功能
每个子应用只完成一个明确任务
VS 只是其中一个子应用，不和其他功能强绑定
```

### 3.2 产品目标

第一版目标不是做一个超级复杂的完整形象报告，而是做一个轻量、清晰、可快速上线的 AI 形象诊断工具集合。

## 15. 子应用八：VS 风格对比

### 15.1 功能定位

VS 风格对比是一个独立子应用，不和其他子应用强绑定。

它的目标不是输出全局诊断，而是生成视觉冲击更强的对比类海报。

### 15.2 功能目标

用户上传照片后，选择对比方向，系统生成：

```text
VS 风格对比海报
穿搭示例
色卡
场景建议海报
```

### 15.3 输入

```json
{
  "imageUrl": "用户照片URL",
  "compareType": "style_vs",
  "leftStyle": "current",
  "rightStyle": "recommended",
  "scene": "commute"
}
```

### 15.4 可选对比方向

| 对比方向 | 说明 |
|---|---|
| 当前风格 VS 推荐风格 | 最通用 |
| 普通穿搭 VS 显气质穿搭 | 适合营销 |
| 路人感 VS 氛围感 | 适合分享 |
| 随意搭配 VS 精致通勤 | 适合职场 |
| 高饱和 VS 低饱和 | 适合色彩对比 |
| 甜美风 VS 轻熟风 | 适合风格测试 |

### 15.5 输出内容

```text
VS 对比海报
推荐穿搭示例
适合色卡
场景建议
一句话风格建议
```

### 15.6 注意

VS 子应用不需要依赖四季色彩诊断结果，也不需要和穿搭诊断强串联。

它可以独立调用图片模型生成视觉海报，保持结构简单。

## 18. 数据库设计

### 18.1 任务表

```sql
CREATE TABLE ai_image_app_task (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
  task_id VARCHAR(64) NOT NULL UNIQUE COMMENT '任务ID',
  user_id BIGINT NOT NULL COMMENT '用户ID',
  app_type VARCHAR(64) NOT NULL COMMENT '子应用类型',
  image_url VARCHAR(1024) NOT NULL COMMENT '用户上传图片URL',
  params_json JSON DEFAULT NULL COMMENT '用户选择参数',
  status VARCHAR(32) NOT NULL COMMENT 'processing/completed/failed',
  progress INT DEFAULT 0 COMMENT '进度',
  error_message VARCHAR(1024) DEFAULT NULL COMMENT '错误信息',
  result_id VARCHAR(64) DEFAULT NULL COMMENT '结果ID',
  created_at DATETIME NOT NULL COMMENT '创建时间',
  updated_at DATETIME NOT NULL COMMENT '更新时间',
  INDEX idx_user_id (user_id),
  INDEX idx_app_type (app_type),
  INDEX idx_task_id (task_id),
  INDEX idx_status (status)
) COMMENT='AI形象诊断子应用任务表';
```

### 18.2 结果表

```sql
CREATE TABLE ai_image_app_result (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
  result_id VARCHAR(64) NOT NULL UNIQUE COMMENT '结果ID',
  task_id VARCHAR(64) NOT NULL COMMENT '任务ID',
  user_id BIGINT NOT NULL COMMENT '用户ID',
  app_type VARCHAR(64) NOT NULL COMMENT '子应用类型',
  image_url VARCHAR(1024) NOT NULL COMMENT '用户上传图片URL',
  result_json JSON NOT NULL COMMENT '结果JSON',
  poster_url VARCHAR(1024) DEFAULT NULL COMMENT '生成海报URL',
  created_at DATETIME NOT NULL COMMENT '创建时间',
  updated_at DATETIME NOT NULL COMMENT '更新时间',
  INDEX idx_user_id (user_id),
  INDEX idx_app_type (app_type),
  INDEX idx_result_id (result_id),
  INDEX idx_task_id (task_id)
) COMMENT='AI形象诊断子应用结果表';
```

如果数据库不支持 JSON，可改为 LONGTEXT。

## 23. Prompt 管理策略

每个 appType 单独维护一个 Prompt。

```text
prompts/
├── season_color_prompt.txt
├── makeup_prompt.txt
├── hairstyle_prompt.txt
├── hair_color_prompt.txt
├── accessories_prompt.txt
├── outfit_prompt.txt
├── glasses_prompt.txt
└── style_vs_image_prompt.txt
```

不要把所有功能写进一个超级 Prompt。

这样做的好处：

- 更稳定
- 更容易调试
- 更容易单独优化
- 成本更低
- 失败范围更小

## 24. 每个子应用的 Prompt 输出要求

```text
使用“更适合”“建议”“倾向于”等温和措辞

无法判断时输出 uncertain
```

## 29. 开发实现建议

### 29.1 不要做大一统报告

不要开发一个一次生成全部诊断的大接口。

错误方式：

```text
/analyze-all
一次生成全部模块
```

推荐方式：

```text
/create
通过 appType 区分要生成哪个子应用结果
```

### 29.2 不要做复杂串联

不要设计：

```text
先四季色彩
再妆容
再发型
再穿搭
最后整合
```

第一版会过重。

推荐设计：

```text
每个子应用独立运行
需要什么生成什么
```

### 29.3 不要让 VS 依赖其他诊断

VS 已经可以独立生成，就保持独立。

后续如果需要，也可以在 VS 页面增加可选项：

```text
是否参考已有四季色彩结果
```

但第一版不要做。

## 30. 一句话总结

本项目应该从“全量个人诊断报告”调整为“AI 个人形象诊断工具集合”。

首页展示多个独立子应用，用户自选使用：

```text
四季色彩诊断
妆容诊断
发型诊断
发色诊断
饰品诊断
穿搭风格诊断
眼镜诊断
VS 风格对比
```

每个子应用独立输入、独立生成、独立展示。  
VS 风格对比只是其中一个子应用，不做复杂串联，不和其他模块强绑定。

这样开发最快、结构最清晰、成本最低，也方便后续逐步扩展。
